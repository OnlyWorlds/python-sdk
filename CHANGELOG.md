## 0.77.0 (2026-10-27)

- **The lens profile's graph reader**: `world_graph(world, reader, *, lens=None, as_of=None, clock=None, rooms=False, hidden=False, proposed=False, map_space=False)` reads a world as nodes and edges for one reader, over the same snapshot and reader as `resolve_lens`, and returns a `WorldGraph` (`nodes`, `edges`, `edges_cut`, `cut`, `unreadable`). Pure: nothing is stored or written. A node (`GraphNode`) is `{id, type, name, family, icon}`, `family` and `icon` from the distribution's presentation defaults (now generated into `_schema.py` as `ELEMENT_FAMILIES` and `ELEMENT_ICONS`), with `marks` (`room`, `hidden`, `proposed`) on an element of a kind that is out by default and `known_of: True` on a guest's known-of stub, which has no edges out. An edge (`GraphEdge`) is `{source, field, target, index}`, one per element, field and target, from the schema's link fields and the two declared extension links (`x_lens_leads_to`, `x_spine_depends_on`); `index` is the target's place in the list as the reader is served it, and a link held on both ends is two edges. Nodes sort by id and edges by source, field and index, each by code point. Without `lens` the nodes are every element the reader sees less room elements, hidden ones, proposed ones and map space (Map, Pin, Marker, Zone); each flag brings its kind back, and `cut` counts what stayed out. With a lens (a body, or the id of one the reader sees) the nodes are exactly the lens's `kept`, its `cut` rides along unchanged, and no flag adds to it; a lens whose `x_lens` cannot be read gives an empty graph with `unreadable` naming the key, as `resolve_lens` does (`unreadable` is `None` otherwise, and always without a lens). A link to an element that is not a node is counted in `edges_cut` by that element's reason (a lens's cut reason; with a lens, `outside_lens` for one the reader sees that the lens neither kept nor cut, counted for every rung and never part of a lens's cut; without one, one of the four kinds; or `not_visible`), in one order: the lens's reasons, then `room`, `hidden`, `proposed`, `map_space`, `outside_lens`; a reader that is not the owner never carries `anchor_not_visible`, `not_visible`, `hidden` or `proposed`, and a link to an id not in the world is not counted. `hidden` or `proposed` from a reader that is not the owner, or any flag from a public reader, raises `ValueError` naming the flag before anything is read; an owner reading `as` another reader is judged by that reader's rung. It answers the 34 cases of the fixture's `graph` kind (schema-dist serial 81), which the npm SDK runs too; the answers equal the npm SDK's `worldGraph` on thousands of random worlds.

Serial 81 writes the lens profile's graph section, which `world_graph` reads, and the fixture's `graph` kind: the graph tests now run its 34 cases and read its graph tables back through the reader, in place of the package's own copy of the same cases.

## 0.73.0 (2026-10-27)

- **The address profile's readers (schema-dist serial 77): `element_address(address)` and `parse_ow_link(text)`** (`onlyworlds.address`), as the TypeScript SDK's `elementAddress` and `parseOwLink`. One element is named by one triple, the world's id, the type word and the element's id, in three spellings: the site's address `https://www.onlyworlds.com/w/<world id>/<type>/<id>`, `ow://<type>/<id>` inside a world and `ow://<world id>/<type>/<id>` across worlds; a world by itself is `https://www.onlyworlds.com/w/<world id>` or `ow://<world id>`. Both raise `AddressError` (a `ValueError`), whose `reason` is one of the profile's ten names (`AddressReason`), the first check that fails in the profile's order. The parser is written out, not `urllib.parse`: nothing is percent-decoded and case is ASCII case. A mapping with a key it does not know is a `TypeError`. The fixture's 133 cases are its test, and the two packages give the same answer on every input (compared on 54,018 random and adversarial inputs, no disagreement). Schema repinned to schema-dist v0.33.0-dist.77 (from dist.76; same canonical 00.33.00, no schema file moved).

## 0.67.0 (2026-10-26)

When `/me` is refused or missing, a guest has no Character, or its Character cannot be read, the key is left out: absent, never guessed. `FORMAT_VERSION` is now `"0.3.9"`; folders stamped `"0.3.8"` stay valid.
- **`Client.me()`**: `GET /me`, who this key is (`{world, scope, kind, role, membership, character, name?}`).
- **`write_folder` keeps `source` and `exported_as`** like any other world key, so a folder rewritten from a read one (a what-if branch) keeps its parent's verbatim.
- **The OKF export carries `source` and `exported_as`** into `world.md`'s frontmatter as the folder holds them, beside `format_version`, `writable` and the `snapshot_*` keys, so a bundle made from one Character's slice still says so. Before, they would have been noted as not World fields and left out.

## 0.6.0 (2026-10-17)

- **Export a world folder to Open Knowledge Format (OKF) v0.2** (`onlyworlds.okf`): `export_okf(folder, out_dir)` or `python -m onlyworlds.okf FOLDER OUT-DIR` writes one markdown concept per element (fields in the frontmatter, text under headings, links as bundle paths and as markdown links), the World as `world.md`, and an index per type. The same folder gives the same bytes. Nothing is left out in silence: a file the reader skipped, a key that is not a field of its type, or a link that is not an id or points at the wrong type is a note in the returned `OkfReport` (stderr from the command line). Ported from schema-dist's `walk/okf_export.py`, it reads through `read_folder` and the generated schema tables. It differs from the branch on purpose: no `generated` actor (OKF §7 asks for a `human:` actor on hand-written words, and a folder does not say who wrote them), in-prose `ow://` references become links into the bundle, and a text line that already begins with a backslash gets one more, so every escaped line reads back.
- **PyYAML only for OKF**: the export needs the new `okf` extra (`pip install "onlyworlds[okf]"`). `import onlyworlds` still imports nothing outside the standard library.
- **The schema module grows** (same pin, `v0.32.0-dist.23`): `BASE_FIELDS`, `WORLD_FIELDS`, `SECTIONS` (each type's fields under their schema groups, in order), `LINK_TARGETS`, `GENERIC_LINKS` and `EXTENSION_PREFIXES`, generated from the vendored walk like the rest and checked against `FIELD_KINDS` and `GENERIC_PAIRS` at generation.

## 0.5.0 (2026-10-17)

- **Folder format v0.3.8, one id, one file (§4).** A writer never leaves an element's id under both `elements/` and the legacy `spatial/`, and a reader that finds one in both serves the `elements/` copy. `write_folder` already wrote a whole folder under `elements/` only, and `Folder.all_elements()` already served `elements/` on a shared id, so nothing changes in what either does. `FORMAT_VERSION` (the `format_version` a written `world.json` declares) is now `"0.3.8"`; folders stamped `"0.3.7"` stay valid.
- **`Folder.in_both_layouts`** lists the ids found in both layouts, sorted: each is a folder some writer got wrong, which the spec says a reader SHOULD log.

## 0.4.0 (2026-10-16)

- **A retry that meets its own first try still running now waits and replays.** After a timeout the client resends with the same Idempotency-Key; if the first request is still running, keel answers 409 `idempotency_in_flight` with `Retry-After: 1`. The retry policy now retries that 409 (and only that one), so `create` and `bulk` get the first answer's replay instead of an error. `ApiError.is_idempotency_in_flight` names it when the retries run out.

## 0.3.0 (2026-10-15)

- **The door of every write.** `Client(..., agent=True)` sends `X-OW-Agent` on every element write (create, upsert, patch, delete, edit_links, bulk: the operations keel's document declares it on; never on reads or `patch_world`), and keel records those writes as agent-made (`changed_via: "declared"`); keel stores that the header was there, never its value. Off by default, and off in any tool a person uses: it describes the caller. An agent seat's key counts as an agent without it.
- **`push` never sends `changed_by` or `changed_via`**, keel's new read-only record of the last write, for the reason it never sends `created_by`: keel drops them but still restamps the element, so a folder that holds them would rewrite elements for nothing.

## 0.2.0 (2026-10-11)

- **Only if unchanged.** `patch(..., if_match=change_seq)` and `edit_links(..., if_match=...)` send `If-Match`: the write lands only if the element is still at that `change_seq`. When it has moved, nothing is written and `PreconditionFailed` is raised (412 `precondition_failed`), an `ApiError` whose `current` is the element as it is now; `ApiError.is_precondition_failed` names the case. The server never merges. An `if_match` that is not a whole number raises `ValueError` before anything is sent. Without `if_match`, nothing changes. Checked on keel-staging (`tests/test_staging_writes.py`).

## 0.1.0 (2026-10-10)

The first release on PyPI. Python 3.12+, no runtime dependencies.

- **The v2 API client** (`Client`): read, write, link operations, bulk, the change feed (`ChangeWalk`), and the error envelope as `ApiError`. It retries busy and gateway answers (`429`, `502`, `503`, `504`) and honours `Retry-After` (`RetryPolicy`). It never retries a wrong PIN, since each retry counts toward locking the key. The transport is swappable (`Transport`).
- **World folders** (format v0.3.7): `read_folder` and `write_folder`, filenames that match Atlas's, and the World's three unit settings (`length_unit`, `mass_unit`, `distance_unit`) carried like any world key. Reading never changes a file.
- **Export and push:** `export_world` writes an online world to a folder. `push` sends a folder's edits back as the difference from a copy exported before editing (`plan_push` to preview it, a log to resume it). A run stops at the first answer that refuses the key itself. What push never sends is listed in `NOT_SENT`.
- **The schema**, generated from schema-dist `v0.31.0-dist.19` (canonical `00.31.00`): `ELEMENT_TYPES`, `FIELD_KINDS`, and the pinned manifest's hash.
