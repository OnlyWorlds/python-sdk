The package version runs on its own semver; the schema it is generated from is `SCHEMA_DIST_TAG`.

## 0.42.0 (2026-10-23)

- **No tool name in a supertype** (the schema owner's lane rule, Skeld, OW Market h40 #11385, #11386: "a converter never writes its own name into supertype or subtype; where a thing came from is the producer line and its `x_<tool>_` keys, what a thing is goes in the type words"). **Behaviour change in three doors**: an untyped element came in as a Narrative with supertype `kanka` (a Kanka module with no OnlyWorlds type), `notion` (a row of an untyped Notion database) or `legendkeeper` (a LegendKeeper page whose tags name no type, or two); each now comes in with supertype `Article`, as the World Anvil and Campfire doors already write. Nothing else moves: the subtype (Kanka's module folder, Notion's database title), the tags, the `x_<tool>_` keys and every id stay as they were, and a test pins each door's ids to those 0.41.0 gave (Kanka's and LegendKeeper's real exports, Notion's built fixture, LegendKeeper's recorded API answers). No other place in the package writes a door's name into a supertype or subtype.
- **LegendKeeper maps** (`onlyworlds.legendkeeper`; Skeld's ruling, OW Market h40 #11385; Boss's three cases, #11387; Seethe's measured placement, #11426, #11429). From the export file, **a map document becomes a Map**, named `<resource>: <document>` as a hidden page's Narrative is: `width` `max_x - min_x` and `height` `max_y - min_y` from the document's `map` bounds, the bounds kept as `x_legendkeeper_bounds` and `max_zoom` as `x_legendkeeper_max_zoom`; `image_url` the map's `mapId` only when it is an http(s) address, as given and never copied (the image lives on LegendKeeper's host and loads only as long as that account's asset does, which the report says); a bare asset id (the tutorial map's) kept as `x_legendkeeper_map_id`, never written as a URL; `location` when the map's resource became a Location, else `x_legendkeeper_resource` its element id. A map document with no `map` object is a Map with no width, height or image, named so in the report, never zeros. **Each pin becomes a Pin** on its Map: its name, or, for a pin with none, the name of the element it places (what LegendKeeper shows), each named in the report; `element_type` and `element_id` the element its `lk://resources/<id>` uri names; a pin with no uri, or one naming no resource of the export, a Pin with no element, named, never a dangling id. Its place: the bounds are image pixels, but LegendKeeper's `pos` is `[y, x]` in zoom-0 units, an image pixel divided by `2^max_zoom`, y counting down from 0 at the map's top to `min_y`; OnlyWorlds counts image pixels from the bottom left, so `x` is `x * 2^max_zoom - min_x` and `y` `y * 2^max_zoom - min_y`, a half rounded up, the exact pair kept as `x_legendkeeper_pos`, and the report names each map's scale ("positions scaled by 2^2 = 4"). Measured on two pins of Seethe's quay map, an 800 by 600 image with `max_zoom` 2 (OW Market h40 #11426, #11429; Skeld #11428): the first, read at image pixel (127, 110) from the top left, is stored `[-27.5, 32]`, which times 4 is (128, 110): x 128, y 490; the second, read at about (796, 524), is stored `[-131.118, 199.314]`: x 797, y 76. Both fit the scaled reading and neither the unscaled one. A pin on a map with no `max_zoom` gets no x, y (the scale is not known, never guessed), keeps its `pos`, and the report names the map; its icon and label (`iconGlyph`, `iconColor`, `iconShape`, `labelSize`, `labelVisibility`, `isSynced`, any other) together as `x_legendkeeper_pin`. A hidden map document, or one on a hidden resource, is a hidden Map whose Pins are hidden; a pin whose `isHidden` is true a hidden Pin (no real file has a hidden pin or map yet: the tests plant them). Ids UUIDv5 of `legendkeeper:<project>:map:<resource>:<document>` and `...:pin:<resource>:<document>:<pin>`. **The API road keeps 0.41.0's behaviour**: the API's map shape (bounds, pins) is not known, never read on the wire, so a map read through the API stays not imported, and the report now says why.

## 0.1.0 (2026-10-10)

The first release on PyPI. Python 3.12+, no runtime dependencies.

- **The v2 API client** (`Client`): read, write, link operations, bulk, the change feed (`ChangeWalk`), and the error envelope as `ApiError`. It retries busy and gateway answers (`429`, `502`, `503`, `504`) and honours `Retry-After` (`RetryPolicy`). It never retries a wrong PIN, since each retry counts toward locking the key. The transport is swappable (`Transport`).
- **World folders** (format v0.3.7): `read_folder` and `write_folder`, filenames that match Atlas's, and the World's three unit settings (`length_unit`, `mass_unit`, `distance_unit`) carried like any world key. Reading never changes a file.
- **Export and push:** `export_world` writes an online world to a folder. `push` sends a folder's edits back as the difference from a copy exported before editing (`plan_push` to preview it, a log to resume it). A run stops at the first answer that refuses the key itself. What push never sends is listed in `NOT_SENT`.
- **The schema**, generated from schema-dist `v0.31.0-dist.19` (canonical `00.31.00`): `ELEMENT_TYPES`, `FIELD_KINDS`, and the pinned manifest's hash.
